# 維多利亞小輪 — 設計文件（GDD）

> 狀態：v0.2.1 · 1980／1990 兩個年代、八達通、貨票、查核年齡
> 呢份文件係全隊嘅「憲法」。改任何數值或規則，先改呢度，再改 code。

---

## 1. 一句話

> 你係碼頭嘅售票員。船唔會等你。

一隻實時碼頭運作遊戲。玩家喺售票窗口應付一班又一班船，由七八十年代數硬幣撕紙票，一路做到要教客用自助售票機。

---

## 2. 核心：船期係唔可以談判嘅死線

呢隻遊戲同一般「餐廳遊戲」最大分別：

| | 餐廳遊戲 | 我哋 |
|---|---|---|
| 壓力來源 | 客人嘅耐性 | **船期** |
| 可以補救？ | 可以，客嬲都只係走一個 | 唔可以，船照開 |
| 失敗嘅樣 | 數字扣分 | **你睇住架船走，閘外面仲有人** |

因為死線係固定同公開嘅，玩家會自己計數、自己加速。緊張感係**累積**嘅，唔係隨機嘅。

### 簽名時刻：截龍

每班船開出前 **10 秒截龍**。閘一關，之後嚟嘅客全部唔收。

呢個係整隻遊戲嘅節拍器。每 45 秒一次，玩家會經歷：

1. 龍越排越長（開始慌）
2. 廣播「往尖沙咀嘅乘客請盡快入閘」（更加慌）
3. 截龍（鬆一口氣 / 或者想死）
4. 船開（結算呢一班船）
5. 新一班客湧入（重新開始）

**所有設計都要服務呢個 45 秒循環。**

## 3. 四層節奏

| 層 | 時間 | 玩家經歷 |
|---|---|---|
| 秒層 | 每 1–3 秒 | 聽單、撳票種、收錢、出票 |
| 分層 | 每 45 秒 | 一班船走，營業額跳，截龍 |
| 更層 | 3 分鐘 | 收工結算：營業額、失誤、上唔到船人數 |
| 局層 | 幾個鐘 | 年代推進、新航線、新崗位 |

**v0.1 只需要頭三層。** 局層之後才做。

|---|---|---|---|---|
| 1970s–80s | 木櫃位、手寫價目牌、印章 | 硬幣、紙幣 | 預印紙票 | **撕票、蓋章、數硬幣** |

## 5. 崗位：一條抽象階梯

| 崗位 | 動詞 | 玩家做緊咩 | 出錯 |
|---|---|---|---|
| **售票員** | 聽單 → 揀航線 → 揀票種／數量 → 收錢 → 出票 | 操作（用手） | 賣錯票、找錯錢、漏收錢 |
| **閘位** | 睇票 → 放行／攔住 → 處理例外 | 判斷（用眼） | 放錯人上船、塞住條龍 |
| **主任** | 睇全場 → 調配 → 廣播 → 拆彈 | 管理（用腦） | 成個碼頭爆煲 |

由**用手 → 用眼 → 用腦**。三個位係三隻唔同嘅遊戲，同一個世界。

### 5.1 售票員（v0.1 唯一實作）

**五步操作：**

1. **聽單** — 客講：「兩張成人，一張小童」
   - 可能講得好快、好細聲、有口音、講英文
2. **睇貨** — 客人唔會早講，行到窗口才見到佢托住電視／單車
   - 1990 年代要收貨票（只收現金）
3. **揀票種 + 數量** — 撳「成人 ×2」「小童 ×1」
   - 細路睇落唔對路？可以「查核年齡」（見 6.7）
4. **收錢** — 客俾 $5，你要撳找續 $2
   - 現金：要找錢
   - 八達通：人票拍卡，貨票照樣收現金
5. **出票** — 撕票／打票，交俾客

**失誤類型：**

| 失誤 | 幾時發生 |
|---|---|
| 賣錯票種 | 客要小童，你撳成人 |
| 數量錯 | 客要 2 張，你出 3 張 |
| 找錯錢 | 找續計錯 |
| 貨票出錯 | 漏收貨票、收多咗、收錯種類 |
| 查核漏招 | 有人扮小童，你冇查核就照賣 |

### 5.2 閘位（v0.3 才做）

- 客行到閘機 → 拍票／拍八達通 → 閘開 → 過
- 例外：票唔啱航線、票過期、餘額不足、閘機卡住、超大行李、嬰兒車、輪椅（要開側閘）
- 壓力：你唔可以攔住成條龍。放錯人上船 vs 塞住條龍 —— 兩邊都痛。

### 5.3 主任（v0.6 才做）

- 唔再用手，用腦：邊個位塞、邊個位爆
- 動詞：調配後備、廣播、處理投訴、開關閘、應付突發
- 呢個位嘅節奏同前兩個完全唔同 —— 佢係「睇住個系統」，唔係「做一個動作」

## 6. 售票員詳細規格（v0.2）

### 6.1 一更

- **3 分鐘 = 07:00–09:00 早高峰**
- 一班船 **45 秒** → 一更 **4 班船**
- 開船前 **10 秒截龍**

兩個年代嘅節奏一樣，但客量同工具唔同：

| | 1980 年代 | 1990 年代 |
|---|---|---|
| 每班船客量 | 8–11 人 | **13–18 人** |
| 客到齊時間 | 首 30 秒 | **首 26 秒**（更密） |
| 龍上限 | 8 人 | 10 人 |
| 付款 | 全現金 | **65% 八達通、35% 現金** |

> 1990 年代唔係「容易版」。客多成 1.6 倍，八達通幫你追返條龍；
> 但拍唔中嗰下嘅停頓，就係你要還嘅時間。

### 6.2 票價（1980 年代天星）

| 票種 | 價錢 |
|---|---|
| 成人 | $1.5 |
| 小童 | $0.8 |
| 長者 | $0.5 |

> 內部用**整數「仙」**儲存（$1.5 = 150），唔好用浮點數。避免 `0.1 + 0.2 !== 0.3` 呢類問題。
> 找續硬幣只有 $1 / 50¢ / 20¢ / 10¢ 四種，所以所有價錢都必須係 10 仙嘅倍數。

### 6.3 付款

| 方式 | 速度 | 風險 | 幾時有 |
|---|---|---|---|
| 現金 | 慢（要撳硬幣找續） | 會找錯錢 | 1980 年代 |
| 八達通 | 快（一撳即過） | 5% 機會失敗，要再拍 | 1990 年代（v0.2） |

> 現金客如果俾啱啱好，撳「唔使找」（鍵盤 `0`）就完成，唔使逐個硬幣撳。
> 呢個掣任何時候都撳得：按落去等於找續 $0，找錯一樣照計。

> **呢個係售票員位嘅靈魂：快 vs 穩。** 每個客都係一次判斷，冇標準答案。
> 1990 年代嘅客有 65% 拍八達通。你唔可以揀——係客揀。你只能承受。

#### 八達通規則（v0.2）

```
1. 客人物件有 pay: 'cash' | 'octopus'
2. 撳「收錢」後，八達通客入 stage = 'tap'（現金客照舊 'pay'）
3. tapCard() 5% 機會失敗，回傳 true / false
4. 失敗：stage 留喺 'tap'、客人 mood −30、0.8 秒冷卻，再拍
5. mood 跌到 0（即連續失敗 4 次）：客人唔買走人，計「上唔到船」
6. 成功：一次過收足小計，冇找續
```

> **點解要冷卻 0.8 秒？** 因為呢隻遊戲嘅成本係時間，唔係分數。
> 失敗嘅代價，係你睇住條龍長多一個人。

> 八達通客照樣會驗票種／數量。撳錯票，嘟得幾快都係錯。

### 6.4 客量同壓力

- 每班船：1980 年代 8–11 個客；1990 年代 13–18 個客
- 龍超過上限（1980：8 人；1990：10 人），龍尾開始有人走
- 截龍時仲喺龍度嘅人 → 計入「上唔到船」

> 唔用個人耐性計時器。壓力全部來自船期同龍長度。簡化，但唔會唔緊張。
> 八達通客嘅 mood 係唯一嘅「個人耐性」，而且只會因為拍卡失敗而跌。

### 6.5 結算

收工顯示：

- 營業額
- 三類失誤各自次數（1990 年代另外顯示「拍卡失敗」次數）
- 上唔到船人數
- 評級（例如：學徒 / 伙記 / 老手 / 賣飛之王）

> 評級只看失誤同上唔到船。拍卡失敗係隨機，唔計落評級——但佢害你上唔到船。

### 6.6 貨票（1990 年代）

客人**唔會喺對白講**自己有貨。佢行到窗口，你才見到佢托住咩。

| 貨種 | 價錢 |
|---|---|
| 電視 | $12 |
| 雪櫃 | $15 |
| 單車 | $8 |
| 風扇 | $6 |
| 電飯煲 | $5 |
| 木梯 | $4 |

- 每班船大約 **32%** 客人有貨，多數一件，平嘢間中兩件
- 貨票**只收現金**，一定要同人票分開計
- 八達通客：先拍人票（人票總額），再收貨票現金
- 現金客：人票 + 貨票一筆過收，找續照計

**貨票出錯＝要收冇收、收多咗、收錯種類。** 懲罰見 6.8。

> 1980 年代冇貨票 —— 嗰陣冇咁多電器搬上船，留返俾 1990 年代做年代差異。

### 6.7 查核年齡

有細路嘅客，**22%** 會有一個「細路」其實係成人（生晒鬍鬚）。

- 見到提示「個『細路』生晒鬍鬚」，可以撳「查核年齡」（鍵盤 `Q`）
- **查到係成人**：即刻轉做成人票（差價照收），客人心情 −20
  - 畫面會蓋一張大字卡：「查核：17 歲 · 成人／已自動轉成人票，小計 +$0.7」
  - 小計會彈一彈，提示你張單變咗
- **查到真係小童**：張單唔變，但客人唔高興，心情 −20
- **唔查核就照賣小童票**：主任唔滿意，記「查核漏招」，扣評級

```
查核 = 用一個小代價（客人心情），換一次確定
唔查 = 賭佢唔係大人；賭輸就扣分
```

> 只可以喺落單階段查。收咗錢就冇得翻轉。

### 6.8 龍嘅怨氣

前面出錯，後面嘅人會躁：

| 觸發 | 效果 |
|---|---|
| 貨票出錯 | 龍入面**每個客心情 −30** |
| 找錯錢 | 龍入面**每個客心情 −30** |
| 客人心情跌到 0 | 佢即刻走，計「上唔到船」 |

- 心情會跟住個客行到窗口（八達通拍卡失敗再 −30 就可能走人）
- 畫面嘅「後面：正常／唔耐煩／想走」就係龍嘅平均心情
- 一次失誤搞躁成條龍，係故意嘅：錯一次唔止蝕一單

> 票種／數量錯**唔會**搞躁條龍 —— 客人只會覺得你慢，唔覺得你呃錢。
> 貨票同找續錯就係「錢銀問題」，條龍會聽到。

## 7. 遊戲狀態結構（v0.2 實際）

```js
G = {
  era: '1980',           // '1980' | '1990'

  elapsed: 0,            // 一更已過幾多秒
  boatT: 0,              // 今班船已過幾多秒
  boatIndex: 0,
  phase: 'sell',         // 'sell' | 'cutoff'

  money: 0,              // 實收，單位：仙
  leftBehind: 0,         // 上唔到船人數（包括燥到走嘅人）
  errors: {
    wrongType: 0,
    wrongQty: 0,
    wrongChange: 0,
    wrongCargo: 0,       // 貨票出錯
    wrongAge: 0,         // 查核漏招
  },

  queue: [],             // 排緊隊嘅客
  current: null,         // 而家喺窗口嘅客
  speech: '',            // 佢講緊咩

  order: { adult: 0, child: 0, senior: 0 },
  cargo: { /* 貨種: 數量 */ },  // 你撳咗嘅貨票
  stage: 'order',        // 'order' | 'pay' | 'tap'
  tender: 0,             // 客俾幾多現金
  change: 0,             // 你砌緊嘅找續
  due: 0,                // 正確找續（唔俾畫面睇）
  cashDue: 0,            // 今次要收幾多現金（貨票／全單）

  tapLock: 0,            // 拍卡失敗後嘅冷卻（秒）
  taps: { ok: 0, fail: 0 },

  arrivals: [],          // 今班船嘅客幾時到
  arrived: 0,
  over: false,
}
```

### 客嘅結構

```js
{
  id: 1,
  want: { adult: 2, child: 1, senior: 0 },
  pay: 'cash',           // 'cash' | 'octopus'
  mood: 100,             // 0–100：拍卡失敗 −30、查核 −20、前面出錯 −30
  cargo: { tv: 1, ladder: 2 }, // 行到窗口才見到（1980 永遠空）
  fakeChild: false,      // 有細路扮成人
  ageChecked: false,
  ageVerdict: '',        // '' | 'adult' | 'child'
  age: 17,               // 查核之後顯示
}
```

> 客人俾幾多錢（`tender`）唔係喺客人身上，而係喺 `collect()` 嗰刻用玩家砌嘅小計計出嚟。
> 因為客人係為「你賣嘅嘢」俾錢，唔係為「佢想要嘅嘢」俾錢。
> 八達通客冇人票找續，所以人票 `tender = 小計`、`due = 0`；
> 有貨票就再開一次 `cashDue`，收貨票現金。

### 年代數值（`rules.js` 嘅 `ERAS`）

```js
ERAS['1980'] = { minCust: 8,  maxCust: 11, queueMax: 8,  octopus: 0,    cargoChance: 0,    ... }
ERAS['1990'] = { minCust: 13, maxCust: 18, queueMax: 10, octopus: 0.65, cargoChance: 0.32, ... }
```

> 加新年代 = 加一個 `ERAS` key，唔使改 `game.js` 嘅流程。

### 動作事件（組隊同步用）

由第一日就用事件形式寫，之後加組隊唔使重寫。

```
ticket.sell    { customerId, items, tender, change }
ticket.tap     { customerId, items, amount, failed }
ticket.cargo   { customerId, items, amount }
age.check      { customerId, verdict }
gate.pass      { customerId }
gate.block     { customerId, reason }
boat.depart    {}
shift.end      {}
```

## 8. 技術方向

- **純 vanilla JS**，冇 framework、冇 build step
- 一個 `index.html` + 幾隻 JS 檔，用 `<script>` 直接載入
- 狀態全部集中喺 `G`
- 美術用 canvas 程式碼畫（或者先用色塊 + 文字）
- 存檔用 `localStorage`
- 部署：GitHub Pages 或 Cloudflare Pages（免費，有 URL 俾朋友玩）

> 為什麼唔用 framework：兩個新手，冇 build step 就冇「點解跑唔到」嘅問題。改完 refresh 就見到。

### 9.1 刻意唔做嘅嘢

呢啲唔係漏咗，係刻意留返：

- **冇 1990 年代以外嘅年代** —— 一次只加一個年代，睇清楚佢改咗咩
- **1990 年代票價同 1980 一樣** —— 想證明「工具變」就夠好玩，唔靠通脹
- **貨票只喺 1990 年代** —— 1980 年代冇咁多電器搬上船
- **查核只係問年齡** —— 唔做身份證、唔做對白分支
- **冇航線選擇** —— 得一條線，所以自動
- **冇「漏收錢」失誤** —— 因為收錢同出票合併咗一步
- **冇存檔** —— 一更 3 分鐘，輸咗再嚟
- **冇音效** —— 遲啲加
- **冇個人耐性計時器** —— 壓力全部來自船期同龍長度（mood 例外）

```
css/style.css       所有樣式
js/rules.js         數值、票價、生成客人（純邏輯，唔碰畫面）
js/game.js          遊戲狀態 G、主循環、玩家動作
js/ui.js            讀 G，更新 DOM
js/main.js          綁掣、啟動
test/sim.js         自動玩家，唔開瀏覽器都測到規則
test/server.js      本機靜態伺服器
```

**分工建議**：`rules.js` 同 `game.js` 一個人管，`ui.js` + `css` 另一個人管。咁就唔會撞。

每個版本都要**有得玩、有 URL 俾人玩**。呢個係唔爛尾嘅唯一方法。

## 10. 組隊設計（v0.4）

因為售票員同閘位係**上下游**，組隊比一般「各做各」嘅合作更有戲：

- 售票員賣得慢 → 閘位冇人過 → 船照開，空船走
- 閘位塞住 → 售票員賣幾多都上唔到船

真人合作會互相嗌、互相賴。呢個係設計上想要嘅效果。

技術：**host 權威**。一個人開房做 host（佢部機行成個碼頭），其他人 join 做某個位。host 定期廣播狀態，客人嘅動作即刻本地執行 + 傳俾 host 確認。

> 由第一日就假設「每個位可以係真人，亦可以係 AI」。成本唔高，但之後唔使重寫。

## 12. 給新手的提醒

1. **唔好先做美術。** 用色塊同文字先做，玩順咗才畫。
2. **唔好先做養成／存檔。** 核心好玩之前，養成只係裝飾。
3. **唔好一次做三個崗位。** 一個位做好，勝過三個半桶水。
4. **每次改完都要自己玩一次。** 你係唯一嘅品味來源。
5. **數值一定會錯。** 第一次寫嘅數值 100% 唔啱，靠玩去調。
