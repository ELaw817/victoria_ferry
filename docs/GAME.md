## 1. 一句話

> 你係碼頭嘅售票員。船唔會等你。

一隻實時碼頭運作遊戲。玩家喺售票窗口應付一班又一班船，由七八十年代數硬幣撕紙票，一路做到要教客用自助售票機。

---

## 2. 核心：船期係唔可以談判嘅死線

呢隻遊戲同一般「餐廳遊戲」最大分別：

| | 餐廳遊戲 | 我哋 |
|---|---|---|
| 壓力來源 | 客人嘅耐性 | **船期** |
| 可以補救？ | 可以，客嬲都只係走一個 | 唔可以，船照開 |
| 失敗嘅樣 | 數字扣分 | **你睇住架船走，閘外面仲有人** |

因為死線係固定同公開嘅，玩家會自己計數、自己加速。緊張感係**累積**嘅，唔係隨機嘅。

### 簽名時刻：截龍

每班船開出前 **10 秒截龍**。閘一關，之後嚟嘅客全部唔收。

呢個係整隻遊戲嘅節拍器。每 45 秒一次，玩家會經歷：

1. 龍越排越長（開始慌）
2. 廣播「往尖沙咀嘅乘客請盡快入閘」（更加慌）
3. 截龍（鬆一口氣 / 或者想死）
4. 船開（結算呢一班船）
5. 新一班客湧入（重新開始）

**所有設計都要服務呢個 45 秒循環。**

## 3. 四層節奏

| 層 | 時間 | 玩家經歷 |
|---|---|---|
| 秒層 | 每 1–3 秒 | 聽單、撳票種、收錢、出票 |
| 分層 | 每 45 秒 | 一班船走，營業額跳，截龍 |
| 更層 | 3 分鐘 | 收工結算：營業額、失誤、上唔到船人數 |
| 局層 | 幾個鐘 | 年代推進、新航線、新崗位 |

**v0.1 只需要頭三層。** 局層之後才做。

## 4. 雙軸進度

### 4.1 時間軸：年代（改變工具同動詞）

| 年代 | 售票工具 | 付款 | 票 | 新動詞 |
|---|---|---|---|---|
| 1970s–80s | 木櫃位、手寫價目牌、印章 | 硬幣、紙幣 | 預印紙票 | **撕票、蓋章、數硬幣** |
| 1990s | 收銀機、電腦售票 | 八達通（1997 出現） | 打印票 | 打票、拍卡 |
| 2000s | 聯網系統、電子顯示屏 | 八達通普及 | 磁帶票 | 查餘額、轉乘 |
| 2010s | 觸控屏幕 | 信用卡、手機 | QR code | 掃碼、退款 |
| 2020s | 自助售票機、手機 App | 全電子 | 電子票 | 教客用機、修機器 |

> 敘事線（可選）：一個老伙記由 1980 年做到 2020 年，眼白白睇住自己份工被機器取代。唔需要對白，用工具嘅變化講。

### 4.2 空間軸：航線（改變內容同複雜度）

| 航線 | 開放時機 | 加咩複雜度 |
|---|---|---|
| 天星小輪過海線 | 一開始 | 基礎：單程、來回、上下層 |
| 離島渡輪線 | 中期 | 遊客、島民、大件行李、寵物、單車、班次疏 |
| 港澳碼頭 | 後期 | 證件、行李托運、高單價、加班船 |

**v0.1 只做天星小輪過海線。**

## 5. 崗位：一條抽象階梯

| 崗位 | 動詞 | 玩家做緊咩 | 出錯 |
|---|---|---|---|
| **售票員** | 聽單 → 揀航線 → 揀票種／數量 → 收錢 → 出票 | 操作（用手） | 賣錯票、找錯錢、漏收錢 |
| **閘位** | 睇票 → 放行／攔住 → 處理例外 | 判斷（用眼） | 放錯人上船、塞住條龍 |
| **主任** | 睇全場 → 調配 → 廣播 → 拆彈 | 管理（用腦） | 成個碼頭爆煲 |

由**用手 → 用眼 → 用腦**。三個位係三隻唔同嘅遊戲，同一個世界。

### 5.1 售票員（v0.1 唯一實作）

**五步操作：**

1. **聽單** — 客講：「兩張成人，一張小童」
   - 可能講得好快、好細聲、有口音、講英文
2. **揀航線** — v0.1 只有一條，所以自動。多航線時才需要撳。
3. **揀票種 + 數量** — 撳「成人 ×2」「小童 ×1」
4. **收錢** — 客俾 $5，你要撳找續 $2
   - 現金：要找錢
   - 八達通：撳一下，偶爾失敗要重拍
5. **出票** — 撕票／打票，交俾客

**失誤類型：**

| 失誤 | 幾時發生 |
|---|---|
| 賣錯票種 | 客要小童，你撳成人 |
| 數量錯 | 客要 2 張，你出 3 張 |
| 找錯錢 | 找續計錯 |
| 漏收錢 | 未收錢就出票 |

### 5.2 閘位（v0.3 才做）

- 客行到閘機 → 拍票／拍八達通 → 閘開 → 過
- 例外：票唔啱航線、票過期、餘額不足、閘機卡住、超大行李、嬰兒車、輪椅（要開側閘）
- 壓力：你唔可以攔住成條龍。放錯人上船 vs 塞住條龍 —— 兩邊都痛。

### 5.3 主任（v0.6 才做）

- 唔再用手，用腦：邊個位塞、邊個位爆
- 動詞：調配後備、廣播、處理投訴、開關閘、應付突發
- 呢個位嘅節奏同前兩個完全唔同 —— 佢係「睇住個系統」，唔係「做一個動作」

## 6. 售票員 v0.1 詳細規格

### 6.1 一更

- **3 分鐘 = 07:00–09:00 早高峰**
- 一班船 **45 秒** → 一更 **4 班船**
- 開船前 **10 秒截龍**

### 6.2 票價（1980 年代天星）

| 票種 | 價錢 |
|---|---|
| 成人 | $1.5 |
| 小童 | $0.8 |
| 長者 | $0.5 |

> 內部用**整數「仙」**儲存（$1.5 = 150），唔好用浮點數。避免 `0.1 + 0.2 !== 0.3` 呢類問題。
> 找續硬幣只有 $1 / 50¢ / 20¢ / 10¢ 四種，所以所有價錢都必須係 10 仙嘅倍數。

### 6.3 付款

| 方式 | 速度 | 風險 | 幾時有 |
|---|---|---|---|
| 現金 | 慢（要撳硬幣找續） | 會找錯錢 | **v0.1** |
| 八達通 | 快（一撳） | 5% 機會失敗，要重拍 | v0.2（1990 年代） |

> **呢個係售票員位嘅靈魂：快 vs 穩。** 每個客都係一次判斷，冇標準答案。
> v0.1 只有現金，所以未出現呢個選擇 —— 呢個係刻意嘅，等年代推進到 1990 年代才加入。

### 6.4 客量同壓力

- 每班船 **12–18 個客**
- 龍超過 **8 人**，龍尾開始有人走（每 2 秒走一個）
- 截龍時仲喺龍度嘅人 → 計入「上唔到船」

> v0.1 **唔用個人耐性計時器**。壓力全部來自船期同龍長度。簡化，但唔會唔緊張。

### 6.5 結算

收工顯示：

- 營業額
- 四類失誤各自次數
- 上唔到船人數
- 評級（例如：學徒 / 伙記 / 老手 / 賣飛之王）

## 7. 遊戲狀態結構（v0.1 實際）

```js
G = {
  elapsed: 0,            // 一更已過幾多秒
  boatT: 0,              // 今班船已過幾多秒
  boatIndex: 0,
  phase: 'sell',         // 'sell' | 'cutoff'

  money: 0,              // 實收，單位：仙
  leftBehind: 0,         // 上唔到船人數
  errors: {
    wrongType: 0,
    wrongQty: 0,
    wrongChange: 0,
  },

  queue: [],             // 排緊隊嘅客
  current: null,         // 而家喺窗口嘅客
  speech: '',            // 佢講緊咩

  order: { adult: 0, child: 0, senior: 0 },
  stage: 'order',        // 'order' | 'pay'
  tender: 0,             // 客俾幾多
  change: 0,             // 你砌緊嘅找續
  due: 0,                // 正確找續（唔俾畫面睇）

  arrivals: [],          // 今班船嘅客幾時到
  arrived: 0,
  over: false,
}
```

### 客嘅結構

```js
{
  id: 1,
  want: { adult: 2, child: 1, senior: 0 },
}
```

> 客人俾幾多錢（`tender`）唔係喺客人身上，而係喺 `collect()` 嗰刻用玩家砌嘅小計計出嚟。
> 因為客人係為「你賣嘅嘢」俾錢，唔係為「佢想要嘅嘢」俾錢。

### 動作事件（組隊同步用）

由第一日就用事件形式寫，之後加組隊唔使重寫。

```
ticket.sell    { customerId, items, tender, change }
gate.pass      { customerId }
gate.block     { customerId, reason }
boat.depart    {}
shift.end      {}
```

## 8. 技術方向

- **純 vanilla JS**，冇 framework、冇 build step
- 一個 `index.html` + 幾隻 JS 檔，用 `<script>` 直接載入
- 狀態全部集中喺 `G`
- 美術用 canvas 程式碼畫（或者先用色塊 + 文字）
- 存檔用 `localStorage`
- 部署：GitHub Pages 或 Cloudflare Pages（免費，有 URL 俾朋友玩）

> 為什麼唔用 framework：兩個新手，冇 build step 就冇「點解跑唔到」嘅問題。改完 refresh 就見到。

## 10. 組隊設計（v0.4）

因為售票員同閘位係**上下游**，組隊比一般「各做各」嘅合作更有戲：

- 售票員賣得慢 → 閘位冇人過 → 船照開，空船走
- 閘位塞住 → 售票員賣幾多都上唔到船

真人合作會互相嗌、互相賴。呢個係設計上想要嘅效果。

技術：**host 權威**。一個人開房做 host（佢部機行成個碼頭），其他人 join 做某個位。host 定期廣播狀態，客人嘅動作即刻本地執行 + 傳俾 host 確認。

> 由第一日就假設「每個位可以係真人，亦可以係 AI」。成本唔高，但之後唔使重寫。

## 12. 給新手的提醒

1. **唔好先做美術。** 用色塊同文字先做，玩順咗才畫。
2. **唔好先做養成／存檔。** 核心好玩之前，養成只係裝飾。
3. **唔好一次做三個崗位。** 一個位做好，勝過三個半桶水。
4. **每次改完都要自己玩一次。** 你係唯一嘅品味來源。
5. **數值一定會錯。** 第一次寫嘅數值 100% 唔啱，靠玩去調。
